## 1️⃣ قسم نقطة البيع (POS)

### 🟠 1.1 — تعديل الكميات بيغيّر كائنات الـ state في مكانها (mutation)
📍 `src/components/POS.tsx:301-302, 317-318`
```ts
updated[existingIndex].quantity = newQty;      // ← تعديل مباشر لكائن جوه الـ state
```
`[...prev]` بينسخ المصفوفة بس، والكائنات نفسها مشتركة. النتيجة إن نفس كائن السلة موجود كمان جوه `parkedSales` (لأن التعليق بيعمل `cart: [...cart]` — نسخة سطحية كمان في `POS.tsx:795`).
**السيناريو:** تعلّق فاتورة → ترجعها → تغيّر الكمية → تعلّقها تاني → ممكن تلاقي نسخة قديمة اتغيّرت معاها.
**الإصلاح:** `prev.map((c, i) => i === existingIndex ? { ...c, quantity: newQty, total: newQty * c.unitPrice } : c)` + `cart.map(c => ({ ...c }))` عند التعليق.

### 🟡 1.2 — الفواتير المعلّقة عايشة في `localStorage` بس
📍 `src/components/POS.tsx:154-170`
مش في IndexedDB ومش داخلة في النسخة الاحتياطية. تنضيف بيانات المتصفح / إعادة تثبيت = الفواتير المعلّقة تروح. وكمان استرجاع فاتورة معلّقة مابيعملش إعادة تحقق من توفّر المخزون (الجهاز ممكن يكون اتباع) — بيفشل عند الحفظ برسالة عامة.
**الإصلاح:** مخزن `parkedSales` في IndexedDB + إعادة تحقق من المخزون عند الاسترجاع مع تعليم البنود اللي مابقتش متاحة.

### 🔵 1.3 — تكلفة جهاز IMEI بسعر شراء 0
📍 `src/hooks/useStore.ts:544` — `unit.purchasePrice || 0`
لو اتسجّل جهاز من غير سعر شراء، الربح بيتحسب = سعر البيع كله. **الإصلاح:** رجوع لـ `inventoryItem.costPrice` بدل الصفر + تحذير في شاشة IMEI.

## 2️⃣ قسم الصيانة

### ✅ 2.1 — [تم الإصلاح] «تسليم الجهاز» بيفشل بصمت لو التذكرة مش «مكتمل»
📍 الزرار: `MaintenanceBoard.tsx:559-563` · المنطق: `useStore.ts:1465-1468`
```ts
if (!maint || !safe || maint.status !== 'completed' || ...) return null;   // ← بيرجع فاضي
```
```ts
onDeliverMaintenance(...); setShowDeliverModal(false); setShowDetailModal(false);  // ← بيقفل زي ما تكون نجحت
```
**السيناريو الواقعي:** تذكرة «تحت الإصلاح» → الفني يضغط تسليم → يكتب 500 ج → «تأكيد» → المودال يقفل، **ولا التذكرة اتقفلت ولا الـ 500 دخلت الخزنة**. برضه نفس الحاجة لو مفيش خزنة افتراضية (`deliverSafe` بيبدأ `''`).
**الإصلاح:** إما تخفي الزرار لغير المكتمل، أو (الأفضل) ترجّع `{ok,error}` من `deliverMaintenance` وتعرض السبب.

### ✅ 2.2 — [تم الإصلاح] «مصاريف إضافية» بتخصم من الربح ومابتخرجش من أي خزنة
📍 `useStore.ts:1471-1473` + إدخالها في `MaintenanceBoard.tsx:675`
المصاريف دي (مواصلات، فني بره، إلخ) بتقلّل الربح المسجّل على التذكرة بس — **مفيش أي حركة خزنة ولا سجل مصروف**. يعني الخزنة في النظام أعلى من الدرج الحقيقي، والمالية مش شايفة المصروف ده خالص.
**الإصلاح:** عند التسليم، سجّل `Transaction` نوعه `expense` بقيمة `additionalExpenses` على نفس الخزنة (أو خزنة مختارة).

### 🔴 2.3 — تكلفة قطع الغيار مش داخلة المالية (نفس مشكلة الهالك اللي اتصلحت قبل كده)
📍 `useStore.ts:1465-1499`

### 🟠 2.4 — إلغاء تذكرة مابيرجّعش قطع الغيار للمخزون

### 🟠 2.5 — التسليم الجزئي بيضيع الباقي

**الإصلاح:** ربط اختياري بـ `customerId` + تسجيل الفرق كمديونية على العميل زي البيع الآجل.

### ✅ 2.6 — [تم الإصلاح] إضافة قطعة غيار بتفشل بصمت

## 3️⃣ قسم المبيعات والمرتجعات

### 🔴 3.1 — رقم الفاتورة ممكن يتكرر
📍 `useStore.ts:506-510` (وبرضه `generateTicketNumber:1358`, `generateAuditNumber:1043`, والمشتريات الجديدة)
```ts
const count = sales.filter(s => s.invoiceNumber.includes(year)).length + 1;
```
الترقيم مبني على **عدد** السجلات مش على أعلى رقم. بعد أي استيراد نسخة احتياطية جزئية، أو دمج بيانات، أو حذف يدوي من المخزن — الرقم بيرجع لورا ويتكرر.
**الإصلاح:** خُد أعلى تسلسل موجود فعلاً: `Math.max(...) + 1` بعد تحليل الرقم، مش `length + 1`.

### 🔴 3.2 — المرتجع بيعيد كتابة الفاتورة الأصلية
📍 `useStore.ts:678-690`
المرتجع بيعدّل `subtotal / discount / total / paid / remaining / profit` **على نفس الفاتورة**. النتيجة:
- الفاتورة المطبوعة اللي مع العميل مابقتش مطابقة للنظام.
- أي تقرير يومي/شهري اتطبع قبل المرتجع مش هيتطابق مع نفس التقرير لو اتطبع تاني (تاريخ المرتجع مالوش لازمة — التعديل بيرجع على يوم الفاتورة).
- «صافي حركة اليوم» في تقفيل اليوم بيستخدم `sale.paid` المعدّل (`reports.ts:297`).
**الإصلاح المعياري:** سيب الفاتورة زي ما هي (immutable) واحسب الصافي = الفاتورة − مرتجعاتها وقت العرض (`saleReturns` موجودة بالفعل ومربوطة).

### 🟡 3.3 — الجهاز المرتجع بيرجع «متاح» من غير أثر
📍 `useStore.ts:692-694` — الحالة بترجع `available` بدل `returned` (والحالة دي معرّفة في `types/index.ts:56`). يعني جهاز مرتجع بيتباع تاني كأنه جديد ومفيش أي علامة في تاريخه.
