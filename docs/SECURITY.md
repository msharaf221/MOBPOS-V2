# دليل أمان MOBPOS (Security Hardening Guide)

هذا المستخدم يلخص كل طبقات الأمان في النظام وبعضها يحتاج خطوة يدوية منك.

---

## 1) سلاسل POS المترية (دليل تنفيذ الخطوة 8)

### المشكلة
النسخة الافتراضية من سياسات RLS في `supabase/schema.sql` (الخطوة 5) هي
`mobpos_*_allow_all` — أي جهاز يملك Anon Key العام يستطيع قراءة وكتابة بيانات المحل
كاملة (المبيعات، المخزون، الأرصدة...).

### الحل: العزل الصارم بسر المستأجر (Step 8)
تم إضافة «الخطوة 8 — عزل المستأجرين الصارم» في نهاية المخطط (متطابقة في
`supabase/schema.sql` و`src/utils/supabaseSchemaSql.ts` و`mobile/src/utils/supabaseSchemaSql.ts`).

خطوات **يدوية** تحتاج تنفيذها مرة واحدة:

1. أنشئ سراً قوياً (32+ حرفاً) — مثال:
   ```bash
   openssl rand -hex 24
   ```
2. نفّذ «الخطوة 8» كاملة من المخطط في Supabase SQL Editor.
3. أدخل بيانات المستأجر في الجدول المحمي:
   ```sql
   insert into public.mobpos_tenant_secrets(tenant_id, secret_hash)
   values (
     'default-tenant',   -- أو معرّف الترخيص الخاص بك
     encode(sha256('YOUR_STRONG_SECRET'::bytea), 'hex')
   )
   on conflict (tenant_id) do update
     set secret_hash = excluded.secret_hash, updated_at = now();
   ```
4. أدخل نفس السر في:
   - الديسكتوب: الإعدادات ← المزامنة السحابية ← «سر المتجر (Tenant Secret)» ثم احفظ.
   - الموبايل: إعدادات الفرع ← «سر المتجر (Tenant Secret)» ثم احفظ.
5. تحقق: أي طلب بدون الرأس الصحيح سيُرفض 403.

### حدود لازم تعرفها
- **Realtime**: Subscriptions عبر WebSocket تلتزم بـ RLS على Supabase في الوضع الافتراضي
  (postgres_changes يتحقق من صلاحية الجلسة)، لكن أسرع وأضمن إجراء هو التعامل مع فلترة
  المستأجر التي تمت بالفعل في كوب العميل (`tenant_id=eq.*`). لا تسرّب أي بيانات
  إلا داخل اشتراكات مستأجر محدد في ARM الفعلي.
- الأجهزة القديمة التي لم تُدخل السر ستتوقف عن المزامنة بعد تفعيل Step 8 — حدّثها أولاً.

## 2) الشبكة المحلية (LAN Hub) — تم تلقائياً

| الترقيع | الوصف |
|---|---|
| قفل CORS | تم إلغاء `*` — لا استجابة لأي origin خارج أجهزة هذا الجهاز بنفس المنفذ |
| جلسات على القراءة | `GET /api/lan/data` يتطلب الآن جلسة صالحة (الجهاز الرئيسي loopback معفى) |
| SSE مؤمن | `/api/lan/stream` يحتاج `?token=...` أو الرأس العادي — يُسكت اشتراكات القراءة المجهولة |
| Rate Limiting | `/api/lan/auth` حجب 5 دقائق بعد 10 محاولات فاشلة في 15 دقيقة (لكل IP) |
| كشف الهاشات | تم إزالة مصفوفة `users` من رد المصادقة — لم تعد تُرسل هاشات كلمات المرور |
| PIN بزمن ثابت | المقارنة عبر `crypto.timingSafeEqual` لمنع Timing Attack |
| النص العائي | قبول كلمة مرور مخزّنة نصاً مقصور على طوارئ الأدمن الافتراضي فقط |
| تنظيف جلسات | دورية كل 5 دقائق؛ جلسة الشبكة تنتهي بعد 12 ساعة (كما قبل) |
| X-Client-Id | أجهزة LAN ترسل معرّف العميل لكبت الصدى في عمود المزامنة الجانبي |

## 3) مسارات المزامنة السحابية — تم تلقائياً

- **قراءة سجل واحد** بدل تحميل المخزن كاملاً في كل حدث Realtime (`indexedDBUtils.get`).
- **إفراغ الـ Outbox** في معاملة واحدة (`removeMany`) بدل حلقة انتظار متتابعة.
- **ترقيم صفحات `pullCatchUp`**: الجهاز المتأخر جداً يبدأ معاك للنهاية بصفحات 500 سجل.
- **LWW صحيح**: سجلات بلا `updated_at` صريح لم تعد تُقلّد `createdAt` كزمن تعديل
  (كانت تمنع وصول تحديثات السحابة إلى سجل مُنشأ محلياً).
- **نبض الخلفية**: حاجز `consecutiveErrors < 5` أزيل — لن يعلق أي صف حتى نهاية
  انقطاع طويل؛ الـ backoff يحمي من الإغراق.
- **ترقية الإصدار**: صفوف الرفع تستخدم `version = القديمة + 1` بدل `1` الثابت.

## 4) الجوال (MOBPOS Companion) — تم تلقائياً

### الحجب من النسخ الاحتياطي
- Android: `allowBackup=false` + `dataExtractionRules` + `fullBackupContent`
  (ممنوع استخراج مفاتيح Supabase عبر adb backup).
- iOS: ننصح بربط الأسرار بعد ضع يدك (قدّم الرفرف) — الاختبار المطلوب خطوة "كتابة".

### Multi-Branch
- **From Tenant Discovery**: اعتماد تلقائي فقط عندما يحتوي المشروع مستأجراً واحداً.
  إذا وُجد أكثر من مستأجر → طلب إدخال «معرّف المتجر» يدوياً (لا راحة بيانات غريبة).
- **الحذف من Write Atom**: عمليات الكتابة (بيع/مصروف/صيانة) تُرفض إذا كان
  `Tenant ID` فارغاً — مع رسالة توضيحية.
- **Realtime**: اشتراكات الرقابة بفلتر `tenant_id` + كَبت صدى `client_id`.
- **Tombstones**: الحذف الناعم ينتفى من العرض (سابقاً الحذف من الديسكتوب لا يظهر أبداً بالجوال).
- **Read-Modify-Write**: رصيد الخزنة، كميات المخزون، أرصدة العملاء، وصافي الدخول
  تُحسب دائماً من **أحدث نسخة سحابية** قبل الحساب — لا مزيد ضياع تحديثات مالية.
- **ترقية الإصدار** بدل `version: 1` الثابت.

### بيانات وهمية
- إزالة «درهم الربح الوهمي 18%» — لو حقل الربح غايب سيُعرض 0 تواضعاً.
- إصدار التطبيق يقرأ الآن من `package.json` (متغير `__APP_VERSION__`).

## 5) مواضع ما زالت تحتاج قرارات منك (خارج الجولة الحالية)

- **Apple Signing / Android Keystore**: تحتاج حساب مطوّر — لا يمكن إتمامها من هذه الجلسة.
- **Service Worker/الويب**: نسخة الدستور تخزن مفاتيح في localStorage؛ Step 8 يعيد
  الأمان للبيانات أونلاين حتى لو سُرُقت الصفحة.
- **اختبارات E2E للشبكة**: اتبع خطد manual للسناريو المضروب من جهازين.
