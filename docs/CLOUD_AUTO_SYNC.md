# توثيق نظام المزامنة السحابية اللحظية (MOBPOS Cloud Auto Sync)

تم تصميم وبناء نظام **المزامنة السحابية اللحظية (Cloud Auto Sync)** لتمكين مستخدمي **MOBPOS-V2** من العمل بسلاسة عبر أجهزة متعددة (الكمبيوتر الشخصي، أجهزة الكاشير، الهواتف الذكية عبر المتصفح) مع الحفاظ الكامل على فلسفة **Offline-First**.

---

## المعمارية الفنية (Technical Architecture)

```
[ شاشات التطبيق والخدمات (Sales, Inventory, Safes, etc.) ]
                             │
                             ▼
         [ IndexedDB Delta Layer (useIndexedDB.ts) ]
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
   [ IndexedDB Storage ]            [ SyncEngine Interceptor ]
  (تخزين محلي فوري دائم)             (التقاط الفروقات اللحظية)
                                              │
                                              ▼
                                 [ Persistent Outbox Queue ]
                                 (طابور العمليات المعلّقة)
                                              │
                      ┌───────────────────────┴───────────────────────┐
                      ▼                                               ▼
         [ في حالة الأوفلاين (Offline) ]                 [ في حالة الأونلاين (Online) ]
     - تستمر كافة العمليات محلياً 100%             - تفريغ الطابور بحزم (Batch Upserts)
     - تُدمج التعديلات لنفس السجل                   - استهلاك التعديلات عبر Supabase REST
     - تُحفظ في IndexedDB (syncOutbox)              - استقبال التحديثات عبر Supabase Realtime
                                                                      │
                                                                      ▼
                                                       [ Supabase Cloud (Postgres) ]
                                                       - `mobpos_records` (لحظي تفصيلي)
                                                       - `mobpos_stores` (لقطات شاملة)
                                                       - Row Level Security (RLS)
```

---

## الميزات والركائز الأساسية

### 1. Offline-First بنسبة 100%
* جميع عمليات القراءة والكتابة تتم فوراً على قاعدة البيانات المحلية **IndexedDB**.
* النظام يعمل بدون أي تأخير حتى عند انقطاع الإنترنت التام.
* التعديلات التي تتم في وضع عدم الاتصال تُحفظ داخل جدول `syncOutbox` في IndexedDB حتى تصمد في حال إغلاق البرنامج أو إعادة تشغيل الجهاز.

### 2. مزامنة لحظية فورية (Moment-by-Moment)
* عبر الاتصال بـ **Supabase Realtime (WebSocket)**، أي حركة بيع، تعديل سعر صنف، قيد خزينة، أو تحديث صيانة تظهر على الأجهزة الأخرى خلال أجزاء من الثانية.
* **Echo Suppression:** تم تزويد كل جهاز بـ `clientId` فريد مع راية حجب `isApplyingRemote` لمنع التحديثات الصادرة من الارتداد الدائري (Infinite Echo Loop).

### 3. حل النزاعات والحذف الآمن (Conflict Resolution & Soft Delete)
* **Last-Write-Wins (LWW):** يعتمد على الطابع الزمني `updated_at`. عند تعارض تعديلين، فإن التعديل الأحدث زمنياً يفوز تلقائياً.
* **Soft Delete:** عند حذف سجل، يتم تسجيل علامة حذف `deleted_at` لضمان حذفه من الأجهزة الأخرى وعدم قيام جهاز قديم بإعادة إحيائه.

### 4. حماية الأمان وعزل المتاجر (Security & Multi-Tenancy)
* لا يتم استخدام أو تضمين المفتاح السري `service_role` إطلاقاً داخل العميل.
* يعتمد النظام على مستخدم موثوق عبر **Supabase Auth** وسياسات أمان **Row Level Security (RLS)** حيث يقتصر الوصول على سجلات المستخدم المالك `owner_id = auth.uid()`.
* يتم فصل بيانات المتاجر عبر `tenant_id` المشتق تلقائياً من رقم ترخيص المتجر (`license.keyId`).

## مكونات النظام البرمجية

| المكون | المسار | الوظيفة |
| :--- | :--- | :--- |
| **قاعدة البيانات السحابية** | `supabase/schema.sql` | تعريف جداول `mobpos_records` و `mobpos_stores`، الفهارس، سياسات RLS، وتفعيل Realtime. |
| **محرك المزامنة** | `src/services/SyncEngine.ts` | إدارة العميل، طابور الانتظار، البث اللحظي، معالجة الأخطاء والتراجع التكراري الأسي (Exponential Backoff). |
| **طبقة IndexedDB** | `src/hooks/useIndexedDB.ts` | رفع إصدار القاعدة لـ 8، إنشاء `syncOutbox` و `syncMeta`، وتضمين مستمع الفروقات `onStoreDelta`. |
| **Hook واجهة المستخدم** | `src/hooks/useSyncEngine.ts` | ربط حالة المزامنة السحابية ومؤشرات الوقت وقائمة الانتظار بمكونات React. |
| **شارة حالة المزامنة** | `src/components/SyncStatusBadge.tsx` | شارة تفاعلية أنيقة في أعلى الشاشة (Header) توضح الحالة: متزامن / جارٍ المزامنة / أوفلاين / خطأ. |
| **لوحة الإعدادات** | `src/components/Settings.tsx` | لوحة تحكم كاملة: تفعيل/تعطيل، تسجيل الدخول لـ Supabase Auth، رفع وتنزيل اللقطات الشاملة، وتفريغ الطابور. |

## خطوات التفعيل في Supabase لأي عميل أو متجر جديد

1. أنشئ مشروعاً جديداً في [Supabase](https://supabase.com).
2. افتح قائمة **SQL Editor** في لوحة تحكم Supabase واضغط **New query**.
3. انسخ محتويات الملف `supabase/schema.sql` (أو اضغط زر **"نسخ كود SQL كامل"** من داخل إعدادات البرنامج أو الموبايل) والصقها ثم اضغط **Run**.
4. من إعدادات المشروع (**Project Settings > API**):
   - انسخ **Project URL** (مثل: `https://xxxx.supabase.co`).
   - انسخ **Anon / Public Key** (مثل: `eyJhbGciOi...`).
5. في تطبيق **MOBPOS-V2** (الكمبيوتر أو الهاتف):
   - توجه إلى **الإعدادات > المزامنة السحابية** (أو شاشة إدارة الفروع في الموبايل).
   - الصق الرابط والمفتاح واضغط **حفظ الإعدادات**.
   - فعّل مفتاح **المزامنة التلقائية اللحظية**.
   - اضغط **"رفع لقطة شاملة (Snapshot)"** لرفع كافة بضاعة ومبيعات وخزن المحل للسحابة فوراً.
   *(ملاحظة: المزامنة تعمل فورياً وبأعلى سرعة باستخدام Anon Key دون الحاجة لإنشاء مستخدمين في Supabase Auth).*

## مسار الترحيل للبيانات المحلية الحالية (Data Migration Path)

* **للمتاجر التي لديها بيانات سابقة على الجهاز:**
  1. بعد ربط حساب Supabase لأول مرة، يضغط المستخدم على زر **"رفع لقطة شاملة (Snapshot)"**.
  2. يقوم النظام برفع كافة المخازن المحلية الحالية كلقطة أساسية إلى `mobpos_stores`.
  3. بعد ذلك، تعمل المزامنة اللحظية الجزئية تلقائياً لكل حركة بيع أو تعديل جديد دون أي تدخل من المستخدم.
* **لربط جهاز جديد (مثل هاتف أو كمبيوتر ثانٍ):**
  1. أدخل نفس رابط ومفتاح وحساب Supabase على الجهاز الجديد.
  2. اضغط على **"استرجاع لقطة شاملة"** لسحب كافة البيانات في ثوانٍ.
  3. يبدأ الجهاز الجديد فوراً باستقبال التعديلات اللحظية من الجهاز الأول عبر Realtime!
