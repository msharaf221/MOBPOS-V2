# إسراع سيرفر الترخيص — ما تغيّر في 1.0.28 وما الخطوات اليدوية

> يشرح هذا المستند ما تم تنفيذه في الكود، والخطوات اليدوية القليلة من لوحة Render.
> **كل التغييرات متوافقة رجعياً (Backward Compatible):** اللايسنس القديم عند
> العملاء يبقى شغالاً بدون أي إجراء منهم.

---

## لماذا كان بطيئاً؟ (التشخيص)

ثلاثة أسباب تراكمت معاً:

1. **استضافة مجانية على Render** (`https://mobpos.onrender.com`):
   الخدمة تنام بعد حوالي 15 دقيقة خمول، وبعد النوم ينتظر أول زائر
   **30-60 ثانية** (Cold Start) قبل أول رد.
2. **العميل كان ينتظر السيرفر عند الإقلاع**: كانت `verifyStoredActivation()`
   تنتظر إعادة التحقق من السيرفر (مهلة 12 ثانية) قبل إظهار التطبيق.
   فخادم نائم = صاحب المتجر يحدّق في شاشة الترخيص كل تشغيل.
3. **السيرفر يعيد كتابة ملف البيانات كاملاً مع كل نبض `/verify`**
   (حقلَي `lastSeen` و`hits`): عشرات العملاء المتزامنين تسبب تشاحن قرص
   يبطئ معالجة السيرفر المفردة (single-threaded) نفسها.

## ما تغيّر في الكود

### سيرفر التفعيل (v2.1) — `activation-server/server.js`
فصل الكتابة على القرص إلى فئتين:

- **قرارات أمنية** (أول تفعيل، إصدار Machine Token عند ترحيل سجل v1،
  الإلغاء `/revoke`، فك الربط `/release`): تُكتب **فوراً وتنجح قبل إرسال
  الرد** — نفس سلوك القديم تماماً. لو انهار السيرفر لن يُفقد توكن جهاز
  سُلّم لعميل، فلا يظهر لعميل صحيح خطأ `bad_token` يمنعه من العمل.
- **نبض إحصائيات** فقط (`lastSeen`/`hits` في `/verify` الروتيني):
  يُجمَّع ويُدفع بتأخير حوالي 1 ثانية. ضياع هذه العدّادات عند انهيار مفاجئ
  لا يغيّر أي قرار أمني.

**أشكال ردود `/activate` و `/verify` لم تتغير إطلاقاً** — توافق كامل مع
كل نسخ العميل القديمة (v1 و v2) بدون أي تحديث مجبر. والنتيجة: الطلبات
الكثيرة المتزامنة لم تعد تخنق القرص، فالسيرفر أسرع والردود أنظف.

### عميل 1.0.28 — `src/license/engine.ts` + `src/App.tsx`
- **إقلاع فوري:** إعادة التحقق الدورية أصبحت تعمل في الخلفية. التطبيق
  يبدأ فور نجاح الفحص المحلي (التوقيع الرقمي ECDSA + الصلاحية + بصمة
  الجهاز) بدون انتظار الشبكة أبداً.
- **الأمان كما هو:** عند الرفض القاطع من السيرفر (إلغاء / Machine Token
  خاطئ / مفتاح مرتبط بجهاز آخر) تُمسح اللايسنس محلياً كالكود السابق
  حرفياً، ويُبثّ حدث `mobpos:license-revoked` فيقفل التطبيق على شاشة
  الترخيص فوراً. الفرق الوحيد: التحقق لم يعد يعاكس بدء التشغيل.
- مهلة إعادة التحقق: 12 → **6 ثوانٍ** (تعمل بالخلفية فليس هناك حاجة
  لأطول). مهلة التفعيل `/activate` — اللحظة التي ينتظرها المستخدم
  صراحة — بقيت **12 ثانية** حتى لا تفشل على خادم بارد.
- التحقق الدوري بقي **مرة كل 24 ساعة** لكل جهاز، وفشل الشبكة يُعامل
  بسماحية أوفلاين كما كان.

## الخطوات اليدوية المتبقية (لوحة Render)

### 1) نشر سيرفر v2.1 (مهم — بدونها لا يتحسّن السيرفر نفسه)
- إن كانت الخدمة **مرتبطة بمستودع GitHub**: تُنشر تلقائياً مع كل push إلى `main`.
- إن كان النشر يدوياً: **Render → الخدمة → Manual Deploy → Deploy latest commit**.

### 2) تغيير المنطقة (أعلى تحسين بدون تكلفة)
- **Render → الخدمة → Settings → Region** → اختر **Frankfurt** أو
  **London** (الأقرب لعملاء مصر: زمن الشبكة ينزل من 150-300ms إلى
  30-70ms تقريباً). أي تغيير منطقة يعيد النشر تلقائياً.

### 3) (اختياري) ترقية مدفوعة — لا نوم إطلاقاً
- **Render → الخدمة → Change Instance Type → Starter** (حوالي $7/شهر):
  - الخدمة لا تنام إطلاقاً (24/7) — لا اعتماد بعدها على النبض الدوري.
  - معالج وذاكرة أفضل وردود أسرع.
- مع الترقية يمكن إيقاف ووركفلو النبض وقتما تشاء — لم يعد ضرورياً.

### 4) النبض الدوري (يعمل تلقائياً بعد أن يصل الكود إلى main)
- `.github/workflows/keep-license-warm.yml` يضرب `/health` كل 5 دقائق
  (الحد الأدنى المسموح في GitHub Actions) فلا يصل سيرفر Render المجاني
  إلى حالة الخمول أصلاً — **وهذا يفيد العملاء على كل النسخ فوراً
  قبل أي تحديث عند أجهزتهم**.
- اختبار يدوي: تبويب **Actions → Keep License Server Warm → Run workflow**
  → يجب أن ترى في السجل «✅ الخادم رد».
- فشل النبض لا يجعل التشغيل أحمر عمداً (وإلا يمتلئ بريد المالك بإنذارات
  كل 5 دقائق) — يُترك تحذير `::warning` في سجل التشغيل للمراجعة.

curl -w 'DNS: %{time_namelookup}s | TCP: %{time_connect}s | TTFB: %{time_starttransfer}s\n' \
     -o /dev/null -s https://mobpos.onrender.com/health

| الحالة | قبل | بعد |
|---|---|---|
| الخادم صحي | 0.2-0.5 ثانية | 0.05-0.3 ثانية |
| أول رد بعد الخمول | 30-60 ثانية | لا يحدث مع النبض الدوري |
| إقلاع تطبيق العميل 1.0.28 | انتظار حتى 12 ثانية | فوري (التحقق في الخلفية) |

كرر الأمر 3 مرات متتالية؛ الأزمنة يجب أن تبقى سريعة لأن النبض يمنع النوم.
